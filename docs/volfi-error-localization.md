# Volfi B-series rounding: final-step compensation and precision budget

**Research date:** 2026-11-08 (Japan). **Status:** reproducible numerical
experiment, not a certified whole-domain Black inversion.
Baseline branch: `codex/volfi-book-prototype-20261107`;
the public `main` and default `Experimental` solver remain unchanged.

## 1. Set-up and original convergence structure

For normalized OTM price `b` and absolute log-moneyness `h`, the
intrinsic coordinate of volfi is

```text
c = b*exp(h/2), a = log1p(expm1(h)/c).
```

In the conformal B-chart (`a >= 2pi`), the solver evaluates

```text
u = 1/sqrt(a),  p = u*F1(u),  w = p*p,  t = h*p,
z = h*h/(4*pi*pi), q = z/(sqrt(1+z)+1)^2,
v_N = t*(1+q*SUM_N), SUM_N = d1(w)+q*d2(w)+...+q^(N-1)*dN(w).
```

The region imposes `h<=4`, hence
`q<=0.084855435009974`. Importantly, `q^17` is about
`6.13e-19` at the upper h bound. This is not automatically
negligible at the absolute accuracy of a binary64 Black inverse,
because the `d_n(w)` coefficient functions can amplify the term.

The released volfi v0.3.1 direct chart uses `N=16`. Its generated
tables contain **rows 17 and 18**, which the earlier Rust port
had not used. We have retained those exact supplied binary64 coefficients;
there was **no re-fitting** or new market calibration.

## 2. Separating model truncation from binary64 rounding

The original 975 archived seam inputs contain 495 direct-chart inputs,
with independent Black roots computed at 160/240 decimal digits.

| Port/kernel | Test cases | Max rho_J | rho_J >= 1 |
|---|---:|---:|---:|
| Uncompensated book (N=16) | 495 | 2.178765 | 39 |
| Inverse-sqrt correction only | 495 | 1.309957 | 10 |
| Endpoint FMA/TwoSum correction (N=16) | 495 | 0.905019 | 0 |
| B17 with final correction | 495 | 0.905019 | 0 |

A second **independent 832-input** corpus is generated by
`scripts/volfi_book_stress.py`: 264 region-A grid inputs,
312 region-B grid inputs, plus 128 independent random inputs
in each region. It computes binary64 prices and then separately
inverts the **rounded** prices at 100 decimal digits using
high-precision Gaussian erfc, high-precision Vega and bracketed
Newton. The first attempt needed a relative bracketing phase for
extremely small OTM prices; this is part of the reference generator,
not the library solver.

| Port/kernel | Cases | Max rho_J | rho_J >= 1 |
|---|---:|---:|---:|
| Uncompensated book (N=16) | 832 | 1.918310 | 33 |
| Inverse-sqrt only (N=16) | 832 | 1.918310 | 23 |
| Endpoint (N=16) | 832 | 1.285378 | 6 |
| Full twofold Clenshaw (N=16) | 832 | 1.285378 | 6 |
| Endpoint + row 17 (N=17) | 832 | 1.191671 | 4 |
| Endpoint + rows 17,18 (N=18) | 832 | 1.191671 | 4 |
| **B17Final** (row 17 + final reconstruction compensation) | **832** | **0.807092** | **0** |

All of these `rho_J` comparisons use exact stored input bits and
the full root `root_hi+root_lo`. No rounding-limited price generated by
the candidate itself serves as a reference.

A high-precision decimal replay evaluating the **represented**
coefficient polynomials (no intermediate f64 rounding) isolates
the truncation error. On the 832-input corpus:

| Exact represented B polynomial | Max rho_J | >1 |
|---|---:|---:|
| 16 rows | 1.099655 | 2 |
| 17 rows | 0.165029 | 0 |
| 18 rows | 0.101293 | 0 |

Thus **the two large-h failures cannot be fixed by Clenshaw
compensation alone**. At least one extra conformal row is required
for these points. The remaining four B17 failures, even under
full twofold Clenshaw, come from the other finite-precision stages,
including the final volatility reconstruction.

## 3. Recovering the last rounding residual

Let `p = p_hi + p_lo` be the endpoint-compensated B-scale
`u*F1(u)`. For the B17Final candidate, retain the residual when
rounding `p` to a binary64 scalar. Writing

```text
t = RN(h*p)
t_low = fma(h,p,-t) + h*p_rounding_low
m = RN(t*q)
m_low = fma(t,q,-m) + q*t_low
d = RN(m*SUM_17)
d_low = fma(m,SUM_17,-d) + m_low*SUM_17
(v_hi, v_add_low) = TwoSum(t,d)
v = RN(v_hi + (v_add_low + t_low + d_low)).
```

This recovers the local errors of the terminal product/add
after the **already existing** endpoint correction of inverse
square root and Chebyshev evaluation. The `q` and
`SUM_17` inputs are still ordinary binary64; this is not a
general arbitrary-precision implementation.

The implementation is
`src/volfi_book/endpoint.rs::region_b_scale_pair` and
`src/volfi_book.rs::direct_b<...>` with the `FINAL` const generic.
`solver::VolfiBookB17Final` is an opt-in research entry point.

## 4. Same-host scalar timings

The final candidate and Experimental were measured in one benchmark
executable on Linux x86-64, native CPU flags, bench-profile LTO,
4 rotating ABBA/BAAB blocks, 2 rounds, 150,000 calls per invocation.
Input populations are seeded and prepared before timing. Results are
**scalar latency**, not the published C++/GPU volfi throughput.

| Workload | Experimental | B17Final | Candidate change |
|---|---:|---:|---:|
| Chart-only 4,096 inputs | 188.90 ns | 183.79 ns | **-2.71%** |
| Fixed region A | 84.22 ns | 135.47 ns | +60.86% |
| Fixed region B | 190.84 ns | 212.48 ns | +11.34% |
| Broader 4,096-input synthetic distribution | 195.95 ns | 245.76 ns | +25.42% |
| Full API, same synthetic input population | 218.10 ns | 262.38 ns | +20.30% |

The chart-only gain holds in all four paired blocks
(-2.68%, -2.97%, -2.54%, -2.75%). The broader sample has
only `1041/4096` direct-chart cases; the others delegate
to Experimental and incur routing and normalization overhead.

Compared to the previously qualified `Endpoint N=17` alone,
B17Final's final residual recovery adds around **1.60%** latency
on the chart-only mixed workload in a separate same-host ABBA run.
Do not compare absolute timings from different CI runners.

## 5. Remaining proof obligations

The finite stress corpus is **not** a proof of `rho_J<1` on the
whole chart. In particular, passing 1,327 inputs cannot justify
correct rounding, uniform precision, or a different libm/architecture.

A rigorous certificate needs:

1. **Domain cover:** partition the compact `(a,h)` or
   `(a,q)` B-chart including `a=2pi`, `a=700` and its upper
   `h=min(4,.16a+.85)` boundary. Include region A seams and
   the exact binary64 price-cap decision.
2. **Truncation/remainder:** regenerate or certify exact represented
   `d_n(w)` and tail bounds for `n>=18`. The bound
   `q<=0.084856` alone does *not* control coefficient growth
   or cancellation. Use interval Chebyshev/Taylor models and
   analytic continuation to obtain a non-sampled enclosure.
3. **Floating point:** verify `sqrt`, `exp_m1`, `ln_1p`,
   reciprocal, coefficient conversion, Clenshaw rounding,
   branch comparisons, FMA/TwoSum error recovery and final
   output rounding, with explicit relative/absolute underflow
   budgets. The Rust standard library does not guarantee a
   platform-independent 1-ULP bound for all libm calls.
4. **Inverse-conditioning transfer:** bound the source price
   residual and the minimal normalized Vega on each accepted
   interval, then transfer an absolute volatility enclosure
   to the attainable-precision
   `rho_J = abs(v_hat/v_star-1)/(2^-52*(1+b/(v_star*V_star)))`.
5. **Throughput and deployment:** compare production quote
   distributions and the original author's full C++/AVX2
   implementation on an identical CPU/data population. A
   -2.71% restricted scalar advantage is not sufficient for
   production adoption in the presence of +25.42% broad-sample
   regression.

The best theoretical next experiment is **cell-wise remainder
certification for the B17 series** and an inexpensive
*input-only certified routing condition* that selects the direct
method only where its full rounding-plus-truncation budget
falls strictly below `rho_J=1`. Otherwise retain Experimental.

## Reproduction

```sh
# Only the stress generator needs the external research dependency.
python3 -m pip install mpmath==1.3.0
python3 scripts/volfi_book_stress.py --output /tmp/volfi-stress.tsv
cargo run --release --features volfi_book --example volfi_book_stress \
  < /tmp/volfi-stress.tsv

cargo test --features volfi_book --test experimental_adaptive_seeds \
  volfi_book_b17_final_independent_reference_seams -- --nocapture
cargo test --features volfi_book,fma
cargo fmt --all --check
cargo clippy --features volfi_book -- -D warnings

cargo bench --features volfi_book --bench volfi_compare --no-run
# Supply the executable path emitted by Cargo's compiler-artifact JSON.
python3 benches/compare_volfi.py /path/to/volfi_compare_executable \
  --reference experimental --candidate volfi-b17-final \
  --iterations 150000 --rounds 2 --blocks 4 \
  --features volfi_book --flags '-C target-cpu=native -C target-feature=+fma' \
  --output /tmp/volfi-b17-final.json
```

The source repository contains sufficient scripts to regenerate the
independent stress inputs; benchmark artifacts retain compiler/CPU
metadata and round-level timing. No experimental feature modifies the
crate's default `Hybrid` solver.
